  summary: A poste button that hits its team cap right after being used keeps its `.selected` CSS class while becoming `disabled`, so it visually still looks "chosen" even though it's no longer interactive — mildly confusing but not blocking (selecting a different poste works normally).

- source_spec: `_bmad-output/prd-runs/players-assets-trajectories-2026-09-22/stories/2-4-feedback-visuel-des-joueurs.md`
  summary: Poste numbering (Story 2-4) uses a simple count-based label ("<post> <count+1>"), so pre-existing saved exercises with un-numbered poste labels (e.g. "PIV" from before this story) are never migrated — adding a new same-poste player for that team produces a numbered label that coexists inconsistently with the legacy un-numbered one.

Candidate fix: either a one-time migration pass over saved exercises, or switch `getPosteLabel` to compute the next number from the max existing numeric suffix (parsing "PIV N" labels) rather than a raw count, which would also self-heal legacy data over time as it's edited.
