- source_spec: `_bmad-output/prd-runs/players-assets-trajectories-2026-09-22/stories/3-1-selection-dun-type-dasset.md`
  summary: ~~HIGH SEVERITY, FUNCTIONAL BLOCKER~~ **RESOLVED** (2026-09-26, out-of-band fix following Story 3-1) — the Dock's Assets grid buttons were unclickable in the browser.
  evidence: **Fixed.** Root causes (three layered issues, found via `document.elementsFromPoint` tracing): (1) `.assets-grid` was `position: fixed` from before Story 1-2 converted `.dock` to a grid item — changed to `position: absolute` anchored to `.dock` (`bottom: 100%`). (2) `.dock` has `overflow-y: hidden` (to prevent icon wrapping) which clips absolutely-positioned descendants regardless of z-index — added `.dock.assets-mode { overflow: visible; }`. (3) `.assets-back-button` was a `.dock` sibling of the grid with a fixed pixel offset that landed inside the grid's bounds once the grid's real rendered height exceeded that offset, and its `z-index: calc(var(--z-dock) - 1)` then hid it behind grid cells — moved it to be a child of `.assets-grid` itself (top-left corner) and removed the now-conflicting z-index. Also fixed an unrelated syntax typo (extra closing paren in `.assets-back-button`'s `transition` value) found while editing that rule. All three fixes verified via real (non-forced) Playwright clicks: full pipeline (open Assets grid → click "Plot" → click back button → click canvas → Plot placed) confirmed working at both desktop (1600×900) and tablet (1024×600) sizes, with no regression to the Players panel. Files: `web-board/src/css/assets-grid.css`, `web-board/src/css/dock.css`, `web-board/src/js/dock.js`.
