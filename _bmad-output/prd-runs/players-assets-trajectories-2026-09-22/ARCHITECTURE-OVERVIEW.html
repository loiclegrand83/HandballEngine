🎯 Players, Assets & Trajectories

Architecture Overview — Exercise Builder for Board Tactique

Vision

Coaches create custom exercises without rigid templates. Select players (any position, any location), place assets (plots, cones), and draw trajectories linked to specific players. Build a complete exercise in minutes.

✓ Key Achievement: No more manual adaptation of predefined simulations. Full strategic flexibility in <5 minutes per exercise.

Core Design Paradigm

Hybrid Rendering: Canvas + HTML Overlay

Two-layer approach:

Layer 1 (Canvas): Static terrain rendering — drawn once, never changes. This is the court/field background.
Layer 2 (HTML Overlay): Dynamic elements — players, assets, trajectories as absolutely-positioned `
` elements over the canvas. Simplified interactions, easy to move/delete.

Why this works: Separates concerns. Canvas stays simple. Overlay gets cheap re-renders. No canvas redraw on every element placement.

User Flow: Place a Player

1
Coach clicks Dock dropdown → selects Joueurs
2
Sidebar shows player list. Coach selects Équipe A + Poste DC
3
Coach clicks terrain at desired player location (x=150, y=200)
4
State updates: new player object added to state
5
Component re-renders overlay layer → new player div appears at (150, 200) with "DC" badge
6
✓ Coach sees player on screen. Repeat for other players.

Data Model

Clean, Serializable JSON Structure

Each exercise is a JSON object with three arrays:

Player

{ id, equipe: "A"/"B", poste: "AG"/"DC"/…, position: {x, y}, created_at }

Asset

{ id, type: "Plot"/"Cone"/"Haie"/…, position: {x, y}, created_at }

Trajectory

{ id, type: "Course"/"Passe"/…, linked_player_id, path: [{x,y}, …], created_at }
✓ Benefits: Simple JSON → easy to save to localStorage, easy to export to GitHub, ready for undo/redo (v2).

Data Persistence

localStorage + GitHub Sync (Manual)

Primary: Browser localStorage (coach's device, instant save)

Backup: Coach manually syncs to GitHub (export JSON → commit, or import from repo)

No auto-sync. Coach controls when exercises are shared/backed up. Simple, no sync conflicts.

Key Technology Decisions

Decision Choice Why
Framework React or Vue Both handle component state + re-renders cleanly. Final choice at Sprint 1.
State Management Context API (React) or Pinia (Vue) Lightweight, builtin. No Redux-level complexity needed.
Canvas Library Native Canvas 2D API Terrain rendering is simple (lines, fill). No need for Pixi, Babylon, etc.
Coordinate Mapping Canvas pixel coords ↔ HTML absolute positioning (1:1) Simple math. Click (x,y) on canvas = overlay div at (x,y). No complex transforms.
Undo/Redo Deferred to v2 MVP doesn't need it. Coach can delete/re-add. v2 adds state history stack.

Open Questions

These will be resolved during Sprint 1 planning:

  • React vs Vue? Team preference + learning curve. Both work equally.
  • GitHub sync flow? CLI commands, or manual file upload? TBD.
  • Canvas size? Fixed (1000×600) or responsive to viewport? Test on tablet early.
  • Terrain view (demi vs complet)? Per-exercise or per-séance? Clarify with coach.
  • Performance ceiling? How many elements (players+assets+trajectories) before lag? Load test in Sprint 2.

What's Deferred (v2+)

  • ✗ Undo/Redo — too complex for MVP
  • ✗ Collaborative editing — single-coach workflow is simpler
  • ✗ Animation playback — play courses/passes in sequence (fun, not critical)
  • ✗ Tactical AI — "this formation is weak defensively" suggestions
  • ✗ Templates — predefined 3v3, 6v6 formations (nice-to-have)
  • ✗ Video/image attach — annotate exercise with footage
