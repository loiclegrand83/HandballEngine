## Findings

**Diff-scope review (folded in from this session's whole-branch code review, not re-run — see note):** A `bmad-code-review` pass (Blind Hunter + Edge Case Hunter + Verification Gap) ran minutes before this retrospective against the full session diff (`e511723..HEAD`), a superset covering Epic 4's files. Re-running it scoped to just Epic 4 would duplicate evidence already gathered against this exact code. Findings relevant to Epic 4:

- **[fixed, uncommitted]** `setSeanceLinkValue` (`web-board/src/js/planning.js:216`) checked `allSeances` for orphan status without gating on `seancesLoaded`, unlike the chip-level check in `renderCalendar` — inconsistent if the séances fetch ever failed (chip says fine, modal says broken). Fixed: the placeholder option now shows "Séance (chargement…)" instead of falsely declaring "introuvable" until `allSeances` is confirmed loaded.
- **[fixed, uncommitted]** `DOMContentLoaded`'s `await loadSeancesForLink()` before `loadEvents()` (added during Story 4.2 to fix a race condition) had no timeout — a hung fetch would have blocked the calendar from rendering at all. Fixed with a 5s `Promise.race` fallback.
- **[fixed, already committed in 312f2f5]** Story 4.2's own build-time review caught a severe bug before it ever shipped: opening and saving an orphan-flagged event silently erased its `seanceId` (native `<select>` reset-on-no-match behavior). Fixed with `setSeanceLinkValue`'s placeholder-option approach — recorded in `spec-4-2-planifier-seance-et-match.md`'s Review Triage Log.

**Duplication map:** The Monday-start-of-week offset formula `(d.getDay() + 6) % 7` appears twice in `web-board/src/js/planning.js` — once in the new `mondayOf()` helper (`:25`, added for Story 4.1's week view) and once inline in `renderCalendar()`'s pre-existing month-grid computation (`:95`, untouched code that predates this epic). Story 4.1 added a reusable helper without refactoring the month branch to use it — a small, low-risk missed consolidation, invisible in either commit alone.

**Pattern divergence:** None found against the codebase's own conventions. Notably, `renderCalendar()`'s chip rendering uses `.textContent` for every piece of free-text event data (`ev.titre`, `ev.adversaire`) — never `innerHTML` — confirmed via `grep -n innerHTML web-board/src/js/planning.js` (only one match, an empty-string clear, not an interpolation). This is a genuine strength: the same class of HTML-injection bug that had to be retrofitted into `seance.js` via a new `escapeHtml()` helper (Story 3.1's review) never existed in Epic 4's code — it was written correctly the first time.

**Spec-to-implementation reconciliation:**

**Architecture delta:** Not applicable in the traditional sense — this is a vanilla no-bundler, no-module codebase (plain `<script>` tags throughout), so there is no import graph to diff. No new cross-file coupling was introduced: `planning.js` already depended on `/api/seances` (for the "lien Séance" dropdown) before this epic; Story 4.2 read from that same existing dependency rather than adding a new one.

**God-class / size growth:** Not a concern. `web-board/src/js/planning.js` grew from ~272 lines pre-epic to 358 lines post-epic (git_evidence: +104/-22, net +82, entirely within this one file across 2 non-merge commits) — normal growth for a focused, single-purpose file, not runaway growth invisible per-commit.

## Action items

1. **[Remediation, low]** Consolidate `web-board/src/js/planning.js`'s duplicated Monday-offset formula: `renderCalendar()`'s month branch (`:95`) recomputes `(d.getDay() + 6) % 7` inline to find the grid's leading Monday, which is exactly what the new `mondayOf()` helper (`:25`) already does — the month branch's `gridStart` line can call `mondayOf(firstOfMonth)` directly instead. Owner: next dev session touching `planning.js`. Not applied here — proposed only.
2. **[Process lesson]** When a hardening fix guards one consumer of a piece of shared state (here: `renderCalendar`'s orphan check gained a `seancesLoaded` guard during Story 4.2's build), enumerate every other consumer of that same state before considering the fix complete — `setSeanceLinkValue` read `allSeances` the same way and was missed until the whole-branch code review caught it. Applies to any future guard added to shared module-level state in this codebase.
3. **[Process lesson]** When converting a fire-and-forget concurrent `async` call into an awaited/sequential one to fix a race condition (here: `loadSeancesForLink()` before `loadEvents()`), pair it with a timeout or fallback in the same change — sequencing trades the race for a new hang risk that the original fire-and-forget code didn't have. Caught by the whole-branch review, not at the point the sequencing fix was made.
4. **[Decision for the user]** The two fixes above (items covered by findings #1-2 in Findings) are already applied in the working tree but **not committed**. Recommend committing them as a follow-up commit before considering Epic 4 fully closed out. Not committed automatically — this retrospective does not execute code changes.

No accepted deviations to record (no finding was judged "working as intended, stop re-flagging" — pattern divergence and duplication findings above are genuinely open, not accepted).
